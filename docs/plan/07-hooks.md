# 07. 호스트 훅

상태: 상세화 중. 관련 결정: Q02, Q05, Q10, Q14, Q15. 근거: [훅 설계](../spec/project-history-design.md), [훅 CLI](../spec/core-cli-interface.md).

## 목표와 산출물

hooks/hooks.json, 필요한 실행 연결, hook session-start/user-prompt/pre-tool/post-tool을 제공한다. 기존 매니페스트가 참조하는 실제 훅 파일은 아직 없다. 호스트 지원 사실은 공식 자료·설치된 환경에서 재검증한 뒤 호환 범위를 확정해야 한다.

## 기존 이벤트 계약

| 이벤트 | 역할 | 기존 시간 제한 |
|---|---|---|
| SessionStart | 세션 기록, sync, 미전송·누락 기록·답변 감지 | 훅 10초, 내부 작업 8초 |
| UserPromptSubmit | 최근 실질 diff와 초안 부재를 보고 넛지 | 3초 |
| PreToolUse | gh pr create·원격 git push 전에 초안/skip 게이트 | 20초 |
| PostToolUse | PR 생성 성공 후 URL을 기록과 연결하고 요약 제안 | 20초 |

명령 경로는 기존 설계상 CLAUDE_PLUGIN_ROOT 기준이다. agent 검증 훅은 opt-in이며 기존 문서상 Claude Code 전용이다. 실제 호스트 스키마와 지원 버전 확인 전에는 호환 검증 완료로 표시하지 않는다.

## SessionStart 검사

1. 초안과 코드 PR 상태를 확인한다. auto_save: true이고 연결 PR이 open/merged이면 최소 요건 검증 후 전송한다. false면 제안만 하고 연결 PR이 없으면 로컬 유지한다.
2. 현재 브랜치 PR에 기록이 없으면 안내만 한다. 본문·리뷰 번들은 기록 절차에서 수집한다.
3. 전체 과거·최근 PR 누락 검사는 기본 세션 시작에서 제외하고 명시적 요청 또는 별도로 켠 검사에서 수행한다.
4. 상태 갱신 대상 기존 기록의 연결 PR과 답변 대기 질문을 조회하고, 새 답변이 있으면 보완을 제안한다. Q12d의 재개방 감지를 위해 rejected 기록의 연결 구현 PR도 대상에 포함한다. 전체 과거 PR 스캔으로 확대하지 않는다.

출력은 기존 규약상 최대 5줄이다. 최근 범위·조회 한도·반복 안내 억제·우선순위는 미정이다.

## 게이트와 PR 연결

- 초안이 있고 auto_save: true이면 최소 요건 검증과 flush 성공 후 통과한다. skip이면 통과한다.
- 최소 요건을 통과한 초안이 있고 auto_save: false이면 전송 제안만 하고 gate 값과 관계없이 코드 도구 실행을 허용한다(Q15b).
- 네트워크·원격 권한 오류로 전송 실패 시 초안 보존·실패 안내 후 gate 값과 관계없이 코드 작업을 허용하고 다음 자동 저장 시점에 재전송한다(Q15a). 기타 실패는 추가 결정한다.
- 둘 다 없으면 bundle 생성 후 block은 exit 2와 stderr, warn은 additionalContext로 안내.
- git push --dry-run은 제외한다.
- PostToolUse는 성공 응답에서 PR URL을 읽어 refs를 갱신·저장하고 요약을 제안한다. 실패는 exit 0과 stderr 로그라는 기존 규약을 따른다.

## 추가 결정

명령 체인·별칭·서브셸·git -C·복수 push 대상의 감지 범위, 히스토리 내부 push/PR 생성의 재진입 방지, 설정 없음·훅 전체 timeout·검증 실패 등 남은 오류의 허용/차단 동작(네트워크·원격 권한에 의한 전송 실패는 Q15a로 확정), PR 생성 실패 뒤 재시도, PostToolUse 일부 실패 복구를 정해야 한다.

넛지는 N턴의 실제 값, 실질 diff 판정, 마지막 알림 상태 보관을 정해야 한다. opt-in agent 검증의 평가 항목과 실패 동작도 상세화 대상이다.

## 확정 정책의 검증 시나리오

| 조건 | 기대 동작 |
|---|---|
| 결정 인지·보완 | 로컬 저장, 즉시 자동 원격 전송 없음 |
| auto_save true, PR 생성·push 전, 저장 요건 충족 초안 | 자동 전송 성공 후 통과 |
| 세션 시작, auto_save true, 연결 PR open/merged, 저장 요건 충족 초안 | 자동 전송 |
| 세션 시작, 연결 PR 없음 | 초안 로컬 유지 |
| auto_save false, 최소 요건을 통과한 초안 있음 | 초안 자동 전송 없이 제안, gate block/warn 모두 코드 도구 실행 허용 |
| 명시적 기록·전송 요청 | auto_save 값과 PR 유무에 관계없이 저장 절차 수행 |
| 현재 PR에 기록 없음 | 세션 검사에서 안내만, 본문·리뷰 번들 자동 수집 없음 |
| 기본 세션 시작 | 프로젝트 전체 과거·최근 PR 누락 검사 없음 |
| 기존 기록 PR 상태 변경 | auto_save false에서도 상태 동기화 유지 |
| 기록 근거 부족 | 질문 초안 작성 가능, 사용자 승인 전 게시 없음 |
| 네트워크·원격 권한에 의한 자동 전송 실패 | 초안 보존·실패 안내, block/warn 모두 코드 작업 허용, 다음 자동 저장 시점에 재전송 |
| 그 외 전송 실패·검증 실패 | 상세 게이트 동작 미결 |

## 추가 검증 시나리오

각 이벤트 stdin·stdout·stderr·exit code, 대상·비대상 명령, 초안·skip·둘 다 없음, 내부 쓰기 재진입, timeout·오프라인, PR 생성 성공·실패, 훅 미신뢰·비활성 환경의 수동 흐름을 확인한다. 호스트별 실제 fixture와 테스트 범위는 Q05·Q15에서 확정한다.
