# v1 전체 계획

## 목표와 범위

개발 중 결정의 이유와 기각한 대안을 기록하고, 별도 GitHub 히스토리 저장소에서 같은 AI 개발 환경으로 다시 조회한다. 스킬·훅·내부 스크립트로 제공한다.

기존 설계의 v1 플러그인·저장소 전체를 상세화한다. Claude Code와 Codex 지원 목표를 유지하되 호환성의 사실 관계와 시험 조건은 확인해야 한다. 뷰어와 v2 임베딩 검색은 후속 범위다.

## 문서 작성과 구현의 담당 범위

이 에이전트의 작업은 문서 정리와 기획·설계 확정까지다. 제품 코드는 구현하지 않는다. 아래 구현 단계는 별도 구현자가 이어받을 작업 순서와 검증 기준으로 작성한다.

## 기존 설계의 통합 시나리오

1. 새 저장소 또는 기존 저장소로 초기화하고 팀원이 설정 파일로 참여한다.
2. 여러 세션의 결정 초안을 누적하고 PR 생성 시 기록을 연결한다.
3. 코드 PR 머지·닫힘을 다음 동기화에서 기록에 반영한다.
4. 웹에서 만든 PR과 과거·타인의 PR을 소스로 기록한다.
5. 근거가 부족하면 질문하고 답변을 반영하되 확인 여부를 구분한다.
6. 코드 없는 결정을 기록한다.
7. 이유·기각한 대안을 검색하고 출처·미확인 상태와 함께 답한다.
8. 기록이 없으면 기록 없음으로 응답하고 백필을 제안한다.
9. 훅을 사용할 수 없는 환경에서 명시적 스킬·명령으로 기록·조회한다.

정확한 인수 조건은 관련 미결 사항을 확정한 뒤 정한다. 위 목록은 통과 결과가 아니다.

## 확정된 기록·조회 정책

- Q01(B): 불완전한 기록도 원격 저장하고 부족한 부분을 명시해 보완한다.
- Q02: auto_save 기본 true. 로컬은 결정 인지 시 갱신, 원격은 PR 생성·push 전 및 세션 시작 시 연결 PR이 open/merged인 초안을 전송한다. 꺼져 있으면 제안만 하고 명시적 요청으로 전송한다. 기존 기록의 PR URL·상태 동기화는 별도로 유지한다.
- Q03: 질문 내용·대상을 사용자에게 보여주고 승인 후 PR 댓글을 게시한다.
- Q12a/b: 새 결정이 accepted가 되어야 이전 결정을 대체한다. 여러 구현 PR은 전부 머지되어야 자동 accepted로 전이하며 discusses는 제외한다.
- Q12c/d: 모든 구현 PR이 미머지 닫힘이면 rejected, 일부만 닫힘이면 proposed 유지·연결 정리 안내. rejected의 구현 PR이 재개방되면 proposed로 복귀한다.
- Q17: 현재 작업·상태 갱신 대상·대기 질문 중심으로 조회한다. 세션 시작의 기록 누락은 안내만 하며 상세 번들은 기록 시 수집한다. 전체 과거·최근 PR 조회는 명시적 요청 또는 별도로 켠 검사로 제한한다.

## 후속 범위

- 선택 뷰어: React/Vite 정적 사이트, GitHub Pages, 히스토리 조회. 접근 방식·화면은 이번에 확정하지 않는다.
- 자동 질문 게시: v1 개별 승인 원칙을 유지하고 실제 사용 결과를 바탕으로 후속 검토한다.
- v2: 임베딩 검색. 기존 search 인터페이스를 유지하며 모델·인프라·도입 기준은 이번에 확정하지 않는다.
