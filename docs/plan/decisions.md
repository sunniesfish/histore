# 설계 결정 관리

## 확정된 작업 범위

2026-09-20 사용자 답변: “네, 세 가지 기본안으로 진행”.

1. docs/plan·spec·history 구조를 사용한다.
2. 기존 확정안은 유지하고 누락·모순·새로운 결정은 사용자에게 질문한다.
3. v1 플러그인·저장소 전체를 상세화한다. 뷰어·v2는 후속 단계로 명시한다.

이 승인은 아래 미결 사항의 해결안에 대한 승인이 아니다.

## 작업 담당 범위와 최근 답변

사용자: “구현은 니가 안할거야. 근데 일단 b로 결정해둬”. 이 에이전트는 문서·기획·설계만 담당하고 제품 구현은 진행하지 않는다. 상세 계획은 별도 구현자를 위한 실행 기준이다.

직전 질문이 구현 순서(Q04a)와 지원 OS(Q05a) 두 개였으므로 단일 “b”의 적용 대상을 확인한다. 확인 전에는 두 항목을 임의로 확정하지 않는다.

## 답변 반영 규칙

답변을 받으면 결정과 답변 근거를 기록하고 관련 상세 계획 및 현행 규약을 함께 맞춘다. 추가 선택이 필요해지면 다시 질문한다. 질문이 남은 항목은 구현 준비 완료로 표시하지 않는다.
