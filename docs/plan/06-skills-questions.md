# 06. 스킬·비동기 질문

상태: 상세화 중. 관련 결정: Q01, Q03, Q07, Q14. 근거: [공통 스킬](../../packages/plugin/skills/history/SKILL.md), [질문 설계](../spec/project-history-design.md).

## 목표와 산출물

공통 SKILL.md가 참조하는 init.md, record.md, ask.md를 작성하고 내부 명령에 연결한다. skip 흐름과 ask-comment, 질문 답변 감지·반영 규칙을 함께 정한다.

## 기존 기록 원칙

코드에 보이지 않는 이유, 기각한 대안, 되돌리기 비용이 크거나 경계를 넘는 결정을 기록한다. 결정 하나당 엔트리 하나이며 추측으로 빈 근거를 채우지 않는다. diff에서만 추론한 문장에는 추정 마커를 붙인다.

## record 흐름의 상세화 대상

1. status로 초안·skip·연결 PR·기존 엔트리를 읽는다.
2. bundle로 초안·대화·이슈·PR·리뷰·diff 근거를 읽는다.
3. 기록 기준에 해당하지 않으면 skip, 해당하면 결정 단위로 작성한다.
4. 근거·대안이 부족하면 구체적인 질문을 엔트리당 최대 두 개 한다.
5. template와 draft write로 기록한다. Q01에 따라 불완전한 기록도 원격 저장할 수 있다. 최소 내용은 결정 내용과 출처다(Q07a). 부족한 부분은 메타데이터 목록과 본문 설명으로 표시한다(Q07b). 목록은 Q07c의 missing 필수 배열 규격을 따른다. URL 없는 대화 출처는 Context에 발언자·날짜·근거 요약으로 남기며 refs: []를 허용한다(Q07d). 부분 누락 판정은 후속 확정한다.
6. 대화 중 자동 기록은 로컬 저장에서 끝낸다. 명시적 기록·전송 요청은 flush까지 수행한다. 자동 원격 전송은 Q02의 PR 작업·세션 시작 조건에 따른다.
7. 타인 질문은 내용·대상을 사용자에게 보여주고 승인 후 게시한다(Q03 확정). 중복·묶음·답변 처리 상세는 Q14에서 정한다.

## init·ask·skip

- init: 인증 확인 → 새/기존 저장소 선택 → 생성·연결 → 설정 작성 → sync 및 호스트별 사용 안내.
- ask: 동의어·관련어 확장 → search → show → 대체 체인 확인 → 출처·미확인 표시. Q13a에 따라 불완전한 기록도 검색하고 후보의 missing으로 공백을 확인한다. 확인된 내용만 답하고 모르는 이유는 미기록으로 설명한다. 기록 없음은 명확히 답한다.
- skip: 현재 브랜치에 마커를 기록하고 한 줄 확인. 유효 기간과 기존 초안 처리 규칙은 Q08에서 정한다.
- 공통: 비단순 파일 수정 전 related로 기존 결정을 확인한다. 프로젝트 저장소에 기록 파일을 직접 쓰지 않는다.

## 질문 게시와 답변

기존 ask-comment는 PR 번호·entry id·questions 파일을 받아 질문, 작성자 멘션, 숨은 history:q 마커를 게시한다. 질문 URL은 엔트리 refs에 discusses로 추가하고 저장한다.

PR당 코멘트 하나와 엔트리별 마커의 관계가 불명확하다. 여러 결정의 질문을 묶는 방식, 이미 게시한 질문 수정, 타인의 댓글을 답변으로 판정하는 기준, 부분 답변 반영과 명시적 확인 증거의 구체적인 처리, 봇·부재 작성자 대체 기준을 확정해야 한다.

Q01은 B로 확정했다. 기존 비동기 흐름처럼 불완전한 기록을 원격에 저장한 뒤 PR 질문과 연결하고, 답변을 받으면 해당 기록을 보완한다. 최소 내용은 결정 내용과 출처로 확정했고, 불완전한 부분은 메타데이터 목록과 본문 설명으로 표현한다(Q07b). 목록 규격은 Q07c의 missing 배열, URL 없는 대화 출처는 Q07d의 Context 표현을 따른다. 댓글은 개별 승인 후 게시하며 v1 자동 게시 기능은 제공하지 않는다. 자동 게시 검토는 후속으로 이관한다.

## 기록 확인 (Q14a 확정)

근거 질문에 답한 것과 에이전트가 작성한 기록을 확인한 것은 구분한다. 답변을 근거로 본문과 missing을 보완할 수 있지만, 결정자가 해당 기록 내용을 명시적으로 확인하기 전에는 verified_by를 자동으로 채우지 않는다. PR 머지와 missing: [] 역시 확인 근거가 아니다.

확인 여부와 무관하게 Q01·Q07a의 조건을 충족한 기록은 저장할 수 있다. Q14b에 따라 결정·이유·대안·결과의 의미가 바뀌면 기존 확인을 해제하고 재확인한다. PR URL·상태·서식만 바뀌면 유지한다. Q14c에 따라 실제 확인한 결정자 목록을 남기며 전원 확인을 요구하지 않는다. 답변에서는 실제 확인한 사람을 명시한다. 확인 목록 원소·대화/PR의 확인 증거 보관·의미 변경 판정 방법은 추가 질문 대상이다. 확인을 받기 위해 별도 댓글을 자동 게시하지 않는다.

## 검증할 시나리오

자신의 브랜치·타인 PR·과거 PR·코드 없는 결정, 여러 결정 분리, 근거 부족, 대안 없음, 질문 승인 거절, 중복 게시 시도, 부분 답변, 미확인 답변 표시, 약한 검색 결과를 다룬다. Q03에 따라 질문 내용·대상 승인 전에는 댓글을 게시하지 않는 동작을 확인한다. PR 상태 조회·기록 누락 안내만으로 댓글이 게시되지 않아야 한다.
